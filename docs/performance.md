# Performance measurements

Measured on 2026-10-01, macOS ARM64 (`macOS-26.3.1-arm64-arm-64bit-Mach-O`).

Toolchain: rustc 1.98.1 (48a229cea 2026-09-01) (Homebrew), Apple clang version 17.0.0 (clang-1700.6.4.2), Python 3.14.7. Both C and Rust use the existing `-O2` / `opt-level=2`; no new runtime dependencies.

## End-to-end results

Each case uses three warmups, then 15 fresh processes per binary. Binary order is shuffled with a fixed seed in every round. Timings include process launch, replay, rendering, encoding, and file close. Profiling is disabled for these runs. The original is commit `f0a7993`; the baseline is that source with instrumentation only.

| Workload | Original median / p95 (ms) | Optimized median / p95 (ms) | Speedup | PNG bytes, before → after |
| --- | ---: | ---: | ---: | ---: |
| reply-sent | 138.22 / 162.50 | 22.54 / 23.70 | 6.13× | 268,702 → 224,071 |
| draft-ready | 140.63 / 146.71 | 21.86 / 32.78 | 6.43× | 262,291 → 218,448 |
| blank | 140.35 / 167.48 | 11.64 / 12.66 | 12.06× | 127,329 → 95,469 |
| dense | 120.82 / 253.22 | 37.23 / 44.57 | 3.25× | 627,877 → 549,190 |
| ansi-replay | 171.59 / 194.46 | 37.62 / 52.10 | 4.56× | 268,702 → 224,071 |
| large | 711.09 / 909.97 | 151.33 / 241.50 | 4.70× | 1,879,677 → 1,537,313 |
| unicode | 44.02 / 46.72 | 19.88 / 23.85 | 2.21× | 211,632 → 187,856 |

`reply-sent` and `draft-ready` use the real sample logs at 100×30 cells / 48 px. `blank` uses the same dimensions. `dense` fills the grid with repeated ASCII. `ansi-replay` repeats the sample 250 times (4,716,750 input bytes). `large` uses 240×80 cells / 48 px (5280×3840 pixels). `unicode` cycles through 800 codepoints at 100×30 / 24 px, including missing glyphs and cache collisions. Fixtures are generated by `scripts/bench.py`.

All raw samples, profile records, binary hashes, output sizes, and compiler versions are in [performance-results.json](performance-results.json). p95 uses the nearest-rank method; with 15 samples it equals the slowest observed run. There are visible scheduling outliers, including a 2.5-second instrumented-baseline large-image run. No samples were discarded. These are warm-filesystem-cache measurements on one shared machine, not cold-disk or cross-platform speed guarantees.

## Where the time goes

Separate profiling runs (15 per binary) give these median times for `reply-sent`. The baseline uses the same timers as the optimized version. Row medians need not sum to the median total.

| Stage | Baseline (ms) | Optimized (ms) |
| --- | ---: | ---: |
| input_read | 0.0441 | 0.0296 |
| parse | 0.1673 | 0.0662 |
| font_read | 0.0650 | 0.0620 |
| font_setup | 0.0070 | 0.0070 |
| allocate | 0.0030 | 0.0030 |
| background | 1.6560 | 0.8700 |
| foreground | 1.6340 | 0.6700 |
| geometry | 0.0830 | 0.0640 |
| glyph | 1.1890 | 0.2770 |
| blend | 0.3080 | 0.2630 |
| png_filter | 9.5890 | 3.9960 |
| png_deflate | 123.2880 | 11.7600 |
| png_pack | 0.7980 | 0.6630 |
| png_encode | 133.9320 | 16.4830 |
| output_write | 0.2740 | 0.2470 |
| cleanup | 0.0010 | 0.0010 |
| total | 137.9007 | 18.5115 |

`geometry`, `glyph`, and `blend` are nested inside `foreground`; `png_filter`,
`png_deflate`, and `png_pack` are nested inside `png_encode`. Do not add parent
and child values together. `glyph` includes lookup, cache management, allocation,
and rasterization. Geometry timing includes dispatch for ordinary characters.

`font_setup` includes font initialization, metric calculation, and the existing
stderr dimensions line. `allocate` is the image `malloc`; first-touch page costs
appear in `background`. `output_write` includes opening, writing, closing, and
freeing the encoded PNG. `cleanup` frees the raster and font. `total` starts in
Rust `main` and includes argument handling and profile output from C; process
startup, final process teardown, and scheduler overhead are only in CLI wall time.
Writes are measured through `fclose`, with no `fsync` durability guarantee.

Font loading and image allocation are already tiny. Their run-to-run differences
are noise, not evidence of an optimization. Input and output I/O each remain a
single read/write sequence. The large-image write median actually rose from
0.503 to 0.694 ms in this run, despite a smaller file; no I/O speedup is claimed.

## Changes and tradeoffs

- **ANSI replay:** borrow CSI parameters and consume SGR parameters with iterators,
  avoiding the parameter and SGR value vectors. Defaults and malformed/short
  parameter behavior are preserved. The long replay's parsing median drops from
  29.21 to 12.48 ms.
- **Glyphs:** keep a bounded 256-slot cache for one render, sharing coverage across
  colors and bold text. Collisions evict safely; missing glyphs are cached too.
  Sample rasterizations drop from 462 to 63, with 399 cache hits. The large case
  drops from 17,280 rasterizations to 22. Unique/colliding Unicode can still miss;
  the cache does not grow with the number of codepoints.
- **Background and compositing:** paint one background scanline per terminal row
  and copy it through the cell height. Clip glyph bounds once before blending.
  Integer blend rounding and geometric drawing remain unchanged.
- **RGB raster:** alpha was always 255. Removing it reduces the sample image buffer
  from 12,672,000 to 9,504,000 bytes and the large image from 81,100,800 to
  60,825,600 bytes, exactly 25%. Filter input shrinks similarly. PNG color type is
  now RGB; decoded opaque colors are identical, but file bytes differ. These
  buffer counts are not peak RSS: compression tables, cache entries, font data,
  and overlapping encoder buffers also consume memory. Peak RSS was not measured;
  the local sandbox denied the system query used by `/usr/bin/time -l`.
- **PNG filtering:** identical adjacent rows use a zero Up filter immediately;
  a zero-score filter ends the search. Other rows retain adaptive filtering.
- **DEFLATE:** search recent matches first, reject candidates unable to improve
  the best match, stop at maximal length, skip impossible lazy improvements, and
  compare long runs in unaligned-safe eight-byte chunks. Compression level and
  lossless output are preserved. The sample's DEFLATE median drops from 123.29
  to 11.76 ms. Local stb edits are tracked in [CHANGES.md](../third_party/stb/CHANGES.md).
- **Failure handling:** check short PNG writes and `fclose` errors, release the
  compressed buffer on PNG allocation failure, and fix an existing empty-input
  zlib fallback defect found by the codec tests.

An `-O3` experiment across all seven workloads showed no consistent win over
`-O2` (sample CLI medians 21.75 vs 21.59 ms, large 146.41 vs 148.33 ms), so the
portable build flags remain unchanged. Curved geometry remains on the original
floating-point path to preserve pixels; it accounts for only 0.064 ms in the
sample. No font-loading cache is added to a CLI that loads one font per process.

## Reproduce

From a checkout retaining commit `f0a7993`, choose a destination that does not yet
exist. The helper reads historical source without switching the current checkout.
It builds the original, applies the checked-in timing-only patch, then builds the
instrumented baseline:

```sh
python3 scripts/build-baseline.py /tmp/termshot-baseline
./build.sh
python3 scripts/bench.py \
  --binary original=/tmp/termshot-baseline/original \
  --binary baseline=/tmp/termshot-baseline/baseline \
  --binary optimized=./termshot \
  --runs 15 --warmups 3 --output /tmp/termshot-comparison.json
```

Use `--case reply-sent` (repeatable) to narrow a run. For a future change, retain
the current executable under a different path and pass both binaries. Run the
benchmark on an otherwise idle machine and retain output sizes as well as times;
optimizing speed by silently inflating output should be visible.

```sh
TERMSHOT_PROFILE=1 ./termshot examples/reply-sent.pty /tmp/reply.png \
  third_party/jetbrains-mono/JetBrainsMono-Regular.ttf
SANITIZE=1 UBSAN_OPTIONS=halt_on_error=1 ./tests/run.sh
```

The profile environment variable is enabled by its presence, even if its value is
`0`. It emits two JSON objects prefixed `termshot-profile ` on stderr. Foreground
profiling performs per-operation clock reads; normal CLI benchmarking disables
these. Profiling records come from separate runs and cannot be subtracted from
CLI samples to estimate exact startup time.

## Correctness and remaining work

The 16 golden fixtures were generated with the original binary. Tests decode PNG
filters using Python's standard library, verify CRCs, and compare dimensions and
SHA-256 hashes of RGB pixels. Coverage includes both sample logs, empty input,
geometry at six sizes (including fractional and extreme sizes), clipping, bold,
cache collisions, missing glyphs, ANSI control strings, short SGR parameters, and
seeded random colors/cursor motion. Compression has 4,976 additional round trips
through independent Python/zlib decoding, with AddressSanitizer and
UndefinedBehaviorSanitizer on the C codec and renderer. CI runs the same suite on
macOS and Linux. Local validation was on macOS; Linux CI has been configured but
was not executed in this session. Timing thresholds are intentionally excluded
from shared-runner CI.

PNG encoding still dominates: 16.48 ms of the sample's 18.51 ms profiled total,
and 109.58 ms of the large case's 125.96 ms total. Future work should compare
compressors or SIMD filter implementations with output-size and portability
constraints made explicit. For long captures, parsing now accounts for 12.48 ms
of 31.15 ms; an ASCII/run parser is the next candidate, provided terminal semantics
remain identical. Batch rendering could amortize process and font initialization,
but would require a new API and cache lifetime. None of these measurements prove
an absolute optimum or cover every font, image distribution, storage device, or
hardware architecture.
