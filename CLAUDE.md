# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

termshot replays a raw PTY log (bytes with ANSI escapes) into a cell grid and writes a PNG of the final screen. It has no crates.io dependencies and no Cargo: it is plain `rustc` plus a C compiler, and it links only libc and libm. MSRV is rustc 1.70 (CI checks it), so don't use newer std APIs or syntax.

## Commands

```sh
./build.sh                      # builds ./termshot (C objects → libtermshot_c.a, then rustc src/main.rs)
./test.sh                       # everything: unit tests, C harnesses, CLI checks, pixel goldens
./test.sh --update-goldens      # rewrite tests/goldens.txt after an intended pixel change
SANITIZE=1 ./test.sh            # draw.c under ASan + UBSan (macOS clang only)
SANITIZE=1 ./tests/run.sh       # extended: codec round trips, compressor, geometry, glyph and (Linux) raster alloc failures in the CLI, draw.c pixels, profile
```

`./test.sh` builds the unit-test binary at `target/test/unit` (a libtest harness from `rustc --test src/main.rs`). After one full run you can run tests directly:

```sh
./target/test/unit <name-substring>   # a single test or a filter
./target/test/unit --ignored          # #[ignore] tests only
```

A test for a known bug states the correct behaviour and is marked `#[ignore = "#N: ..."]` with its issue, so it starts passing when the issue is fixed. None are open now. The bare `#[ignore]` on `poc_workloads` is different: that function is a benchmark helper, not a test. It writes inputs to `$TERMSHOT_POC_DIR` and does nothing when the variable is unset (see `docs/c-vs-rust.md`). So is `any_cff2_font_matches_harfbuzz`: given `TERMSHOT_CFF2_FONT` and `TERMSHOT_CFF2_OUTLINES` (written by `tools/cff2-outlines.sh [--variations=LIST] FONT OUT`), it checks each character's glyph against HarfBuzz's outline at that instance (the glyphs termshot can draw; the others need only draw without an error).

Rebuild it after editing Rust without running the whole suite:

```sh
./build.sh && rustc --edition 2021 --test src/main.rs -o target/test/unit -L native="$PWD" -l static=termshot_c
```

Renders from the test run stay in `target/test/` for inspection. When a change is meant to move pixels, look at them first, then update the goldens.

Other tools: `tests/vt/oracle.sh` compares `tests/vt/expected.txt` against tmux (not in CI); `tests/vt/record.sh` records real sessions; `tools/unicode-tables.sh` regenerates `src/unicode_tables.rs` from the UCD (don't edit that file by hand); `tools/rowcolumn-diacritics.sh` regenerates `src/rowcolumn_diacritics.rs`, kitty's Unicode placeholder diacritics, likewise; `scripts/bench.py` benchmarks; `TERMSHOT_PROFILE=1` prints stage timings as JSON on stderr; `scripts/release.sh <platform>` builds a release archive.

## Architecture

The pipeline is Rust in, C out, with the C calling back into Rust for the painting (text, box drawing, images) and compression, and the Rust calling back into stb_truetype only through the functions draw.c hands it:

1. **`src/main.rs`** holds the CLI (`parse_args`), the input handling, and the whole VT parser and screen model: `Screen`, `Pen`, `Cell` (defined with its `attrs` bits in `src/cell.rs`), `parse`/`parse_lf`, `csi`, and `utf8_at`. It follows xterm: autowrap, scroll regions, the alternate screen, DEC graphics, and so on. Output is a flat `Vec<Cell>` of `cols*rows` plus final image placements. `src/cast.rs` decodes asciinema `.cast` input (v2 and v3) into the output bytes and the recording's size (the header's, or the last resize's) before any of this runs; it holds the strict JSON reader, which bounds nesting at `MAX_DEPTH`. `src/graphics.rs` handles the supported kitty direct-transmission subset; `src/image.c` wraps the vendored PNG decoder with a bounded allocator. `src/sixel.rs` decodes Sixel images (DCS `q`) as xterm does and feeds each to the kitty image store as a kitty command (`Graphics::sixel`, which wraps `Graphics::command`), so Sixel shares its layering, scrolling and limits; unlike kitty's, its pixels belong to the cells, and text and ED 0/1 clear them.
2. **`src/font.rs`** validates every TrueType structure stb_truetype will touch before C ever sees the font, because stb trusts its input. A font that fails is refused with a reason (exit 1). Fonts reach C with zero padding after them. JetBrains Mono is embedded with `include_bytes!` as the default.
   **`src/cff.rs`** reads CFF and CFF2 outlines (`.otf`, Noto CJK; CFF2 at any instance, whose coordinates `src/variations.rs` works out from fvar and avar as HarfBuzz does). stb's CFF reader trusts its input, so stb never runs a charstring: `font.rs` checks the CFF table with `cff::Font::parse`, and `src/glyphs.rs` gets each outline through the callback in the `#[repr(C)] Face` (`font::Font::with_face`), then has stb rasterize it with `stbtt_Rasterize`. On a CFF face, nothing may call stb functions that read glyph outlines (`IsGlyphEmpty`, `GetGlyphBox`, `GetGlyphShape`, `MakeGlyphBitmap`); cmap and metrics calls are safe. draw.c hands glyphs.rs those four for a TrueType face only (`glyph_face`), and glyphs.rs refuses a face with both a callback and them (8). `src/cff_tests.rs` compares every glyph with stb's and builds hostile fonts; `docs/cff-rust-vs-c.md` is why this is Rust.
3. **`src/unicode.rs`** and **`src/unicode_tables.rs`** give character widths (wide = 2 cells) and canonical composition for combining marks.
4. **`src/draw.c`** drives a render, behind `draw_png_images` (and the cell-only `draw_png` test wrapper): it sets up the fonts (`init_font`, `init_face`, `init_cff2`) and the cell metrics (`cell_metrics`; `draw_cell_size` shares them with the parser so native-pixel images move the cursor correctly), allocates the raster, calls the painters in order (the backdrop's init, the text (8), the images over the text (6)), writes the PNG through a locally modified `stb_image_write.h` and `src/png_crc.h` for the CRC, and prints the `TERMSHOT_PROFILE` record. It holds stb_truetype, which stays C (#12 step 3), and paints nothing itself; the driver, the metrics and the PNG write are #12 step 2d.
5. **`src/geometry.rs`** paints box drawing and block elements (U+2500–U+259F) as geometry, so lines join at any integer cell size, and keeps `Stamps`, the cache that repaints rounded corners and diagonals from the runs of an earlier stroke when a TwoSum check proves its points sit exactly as far from its cell's origin (4 MiB budget; a failed allocation stamps the stroke afresh, so geometry never fails a render). `src/glyphs.rs` calls it once per cell (`paint_cell`) and for underlines and missing-glyph boxes (`fill_rect`); `termshot_paint_geometry` and `termshot_fill_rect` remain for the C harnesses, and per-pixel calls across FFI are not allowed. The `Canvas` is `#[repr(C)]` and shared (40 bytes, asserted on both sides); its `geometry` pointer is the render's Rust state (`termshot_geometry_new`/`_free`/`_stats`). The float arithmetic is the C's, operation for operation in f32, and `sin_cos` calls the platform's sincos by name (`__sincosf_stret`, `sincosf`) because the C's compilers merged `sinf`/`cosf` into it and on macOS the two forms differ in the last bit (`bench/c-vs-rust/sincos.c`). `bench/c-vs-rust/run.sh geometry` (CI runs it) compares it pixel for pixel with the C it came from. It was C until #12 step 2a.
6. **`src/composite.rs`** paints the image layers into the same `Canvas`: kitty and Sixel images and the underline and bar cursors (solid 1x1 `ImageView`s), sampled nearest-neighbour in integers with crops (`src_*`) and clips (`clip_*`: scrolled slices, Unicode placeholder runs), blended as `(s*a + d*(255-a) + 127) / 255`, in kitty's three layers by z (below the backgrounds under `INT32_MIN / 2`, where only cells without `ATTR_OPAQUE` show them; under the text below 0; over it). It also paints the backdrop under the text: the cell backgrounds, then the two lower layers, a row of cells ahead of the glyphs over them (`Backdrop`, all at once for a raster under 16 MiB or with more than 64 images under the text). `draw.c` fills in a `#[repr(C)] Backdrop` it keeps in its frame (`termshot_backdrop_init`; 48 bytes, asserted on both sides), `src/glyphs.rs` paints it a row at a time as the text reaches each row (`due`, then `termshot_backdrop_through`, timed there), and `draw.c` calls `termshot_paint_images` for the layer over the text. It allocates nothing; a panic (a bug, such as a crop outside its image) is caught, and `termshot_paint_failed` fails the render. `ImageView` is defined here. `bench/c-vs-rust/run.sh images` (CI runs it) compares it with the C it came from on random scenes and through the CLI. It was C until #12 step 2b.
7. **`src/deflate.rs`** is the compressor that PNG writer calls, through FFI: `STBIW_ZLIB_COMPRESS` is `termshot_zlib_compress`, a `#[no_mangle] extern "C"` function in the main crate. It is stb's deflate made faster, with byte-identical output (`tests/deflate_diff.c` checks it against stock stb). Its output buffer comes from libc `malloc`/`realloc`, because stb `free()`s it; every allocation is checked, and a failure returns NULL, which `draw.c` reports as out of memory (exit 2). Adler-32 uses SSE2 intrinsics on x86-64 and a 16-lane loop that LLVM vectorizes elsewhere; that loop's shape decides whether it vectorizes, so check the linked binary after changing it (`docs/c-vs-rust.md`). The C harnesses link it, `geometry.rs`, `composite.rs` and `glyphs.rs` (with `cell.rs` and `cff.rs`) as a static library (`tests/rust_lib.sh`). It was C until #12 step 1.
8. **`src/glyphs.rs`** paints the text, once per render (`termshot_paint_text`): each cell's glyph from the font or else the fallback, through a 1024-slot cache (`Glyph`, `Glyphs::find`; the key is the code point with wide, italic and mark, the slot `(cp ^ (italic ? 512 : 0)) % 1024`, and a conflict replaces the slot); the fallback's scale, centering and shrinking to fit (#27/#47); italic as a 12° slant of the outline (`slant_outline`; box drawing stays upright); bold as a second blend a pixel right; the outlined box of a character neither font has, and the `EmptyGlyphs` report of empty glyphs; combining marks (`paint_marks`: drawn from the end of the character when left of their origin, centered otherwise; default ignorables and Hangul fillers draw nothing); then underlines, double underlines and strike-through. It paints the backdrop (6) a row ahead of the text, and box drawing through (5). stb stays C: draw.c hands it `TextFonts` (152 bytes), two `GlyphFace`s (56) with stb's cmap, metrics and rasterizer functions, and stb's four outline readers for a TrueType face only; a CFF face's outlines come from `Face.outline` (`Outline`, a scratch buffer shared by the empty check and the drawing, invalidated when slanted). The float arithmetic is the C's, operation for operation in f32, and needs no libm call: floor, ceil and round are exact. A failed allocation (the slots, the scratch, a bitmap) returns 1 and draw.c fails the render ("glyph allocation failed", exit 2); a panic returns 3 ("painting failed"). It reports its timings and counters in `TextStats` (80). `bench/c-vs-rust/run.sh glyphs` (CI runs it) renders every fixture and generated logs with each kind of font at several sizes through the CLI built from the old draw.c and through this one, and compares the PNGs and stderr byte for byte. It was C until #12 step 2c.

`Cell` is `#[repr(C)]` and shared across the FFI boundary: `draw.c` asserts `sizeof(Cell) == 12` (and both sides assert `ImageView`'s 104 bytes, `Canvas`'s 40, `Backdrop`'s 48, `Face`'s 32, `GlyphFace`'s 56, `TextFonts`'s 152 and `TextStats`'s 80), and the `ATTR_*` bits are defined in both languages. Change both sides together. All eight `attrs` bits are taken. Combining marks with no precomposed form live outside `Cell`, in `Screen::marks` (keyed by storage index, kept in step by every edit) and then `Grid::marks`, a sorted `CellMarks` list (cell index plus `MAX_MARKS` = 4 code points, in `src/cell.rs`) that draw.c passes on to `src/glyphs.rs`; `marks_of` looks a cell up.

Unit tests live in `src/tests.rs` and `src/draw_tests.rs` (both `#[cfg(test)]` modules of main.rs), and beside the modules they test (`src/geometry_tests.rs`, `src/glyphs_tests.rs`, which drives the glyph code with fake stb functions, `src/deflate_tests.rs`, ...). They check the parser against the screens in `tests/vt/expected.txt` and `tests/vt/real/`. Pixel goldens (`tests/golden.rs`) hash *decoded RGBA pixels*, not PNG bytes, so encoder changes that keep the pixels don't break them. The same runs write `--text` and `--json`, compared byte for byte with `tests/grids/<log>.txt` and `.json`; `--update-goldens` rewrites all of them, and `tests/grids/check.py` checks that the JSON agrees with the text. The text rows are also what the `tests/vt/` checks compare, so the tmux references cover `--text`.

## Constraints that aren't obvious

- **Determinism across platforms is a feature.** The same input must give the same pixels on macOS arm64, x86-64 Linux, and aarch64 Linux, with glibc or musl. `draw.c` is built with `-ffp-contract=off` so Apple clang doesn't fuse multiply-adds, which would change pixels (px 46 is in the goldens to catch exactly this). Never add `-ffast-math`. The Rust painting code must not use `mul_add`, and calls libm's rounded functions as the C's compilers did (see `geometry.rs`; `glyphs.rs` needs none).
- The C is linked as a static library (`-l static=termshot_c`), not as bare objects, so rustc orders it before libc and libm. That ordering is what makes static musl and glibc on aarch64 link. It calls back into the crate (`termshot_zlib_compress`, the deflate profile functions and the `termshot_*geometry*`, `termshot_backdrop_init`, `termshot_paint_text` and `termshot_paint_images` painters), which links because the crate's own objects come first. The Rust names no symbol of draw.c's: stb's functions reach `glyphs.rs` as pointers, so the harnesses' static library links without draw.c. Keep `build.sh`, `test.sh`, `tests/run.sh` and `scripts/release.sh` consistent if you change the link line.
- Local changes to vendored stb are listed in `third_party/stb/CHANGES.md`; record any new ones there. `stb_truetype.h` is unmodified.
- CLI exit codes are part of the contract: 0 done, 1 unreadable or unwritable file, malformed `.cast`, or bad font, 2 bad arguments (including an image over 2^27 pixels, a cast larger than 500x200 without `--size`, and an output that names an input or another output) or an allocation failure in `draw.c`, the glyph painting or the compressor (or a panic in a painter), whose return code `main` passes through; an allocation failure in the geometry caches is not a failure, the stroke is painted uncached. A failed run removes the output files it created (the PNG, `--text` and `--json`). It is quiet on success, except for the hint about `--lf-newline` and the warning for a character drawn as a box because a font maps it to an empty glyph (`src/glyphs.rs` reports it in `EmptyGlyphs`; `main.rs` words it). `test.sh` checks all of this, and `tests/run.sh` fails each compressor allocation (exit 2), each geometry allocation (same PNG), each glyph allocation (exit 2) and, on Linux, the raster's (exit 2) in the CLI.
- A bare LF moves down without a carriage return, as in a real terminal. `--lf-newline` exists for logs not captured through a PTY, such as `tmux capture-pane`.
- User-visible changes go in `CHANGELOG.md` under `[Unreleased]`, in Keep a Changelog format.
