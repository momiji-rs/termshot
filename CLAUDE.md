# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

termshot replays a raw PTY log (bytes with ANSI escapes) into a cell grid and writes a PNG of the final screen. It has no crates.io dependencies and no Cargo: it is plain `rustc` plus a C compiler, and it links only libc and libm. MSRV is rustc 1.70 (CI checks it), so don't use newer std APIs or syntax.

## Commands

```sh
./build.sh                      # builds the C objects → libtermshot_c.a, the library libtermshot.rlib (rustc --crate-type rlib src/lib.rs, the C inside), then ./termshot (rustc src/main.rs --extern termshot=libtermshot.rlib)
./test.sh                       # everything: unit tests, C harnesses, CLI checks, pixel goldens, the library as an embedder links it (tests/library.rs)
./test.sh --update-goldens      # rewrite tests/goldens.txt after an intended pixel change
SANITIZE=1 ./test.sh            # the C (stb_glue.c, image.c) under ASan + UBSan (macOS clang only)
SANITIZE=1 ./tests/run.sh       # extended: codec round trips, compressor, render, parse, geometry, glyph and (Linux) raster alloc failures in the CLI and (parse, render, compressor, glyphs) through the library, whole renders through the sanitized stb glue, profile
```

`./test.sh` builds the unit-test binary at `target/test/unit` (a libtest harness from `rustc --test src/lib.rs`), and the CLI's at `target/test/cli-unit` (`rustc --test src/main.rs`, linking the rlib). After one full run you can run tests directly:

```sh
./target/test/unit <name-substring>   # a single test or a filter
./target/test/unit --ignored          # #[ignore] tests only
```

A test for a known bug states the correct behaviour and is marked `#[ignore = "#N: ..."]` with its issue, so it starts passing when the issue is fixed. None are open now. The bare `#[ignore]` on `poc_workloads` is different: that function is a benchmark helper, not a test. It writes inputs to `$TERMSHOT_POC_DIR` and does nothing when the variable is unset (see `docs/c-vs-rust.md`). So is `any_cff2_font_matches_harfbuzz`: given `TERMSHOT_CFF2_FONT` and `TERMSHOT_CFF2_OUTLINES` (written by `tools/cff2-outlines.sh [--variations=LIST] FONT OUT`), it checks each character's glyph against HarfBuzz's outline at that instance (the glyphs termshot can draw; the others need only draw without an error). `any_cff2_font_s_metrics_match_harfbuzz` is its twin for metrics: given `TERMSHOT_CFF2_FONT` and `TERMSHOT_CFF2_METRICS` (written by `tools/cff2-metrics.py [--variations=LIST] FONT OUT`, which needs libharfbuzz), it checks every glyph's advance and the ascender, descender and line gap.

Rebuild it after editing Rust without running the whole suite:

```sh
./build.sh && rustc --edition 2021 --test src/lib.rs -o target/test/unit -L native="$PWD" -l static=termshot_c
```

Renders from the test run stay in `target/test/` for inspection. When a change is meant to move pixels, look at them first, then update the goldens.

Other tools: `tests/vt/oracle.sh` compares `tests/vt/expected.txt` against tmux (not in CI); `tests/vt/record.sh` records real sessions; `tools/unicode-tables.sh` regenerates `src/unicode_tables.rs` from the UCD (don't edit that file by hand); `tools/rowcolumn-diacritics.sh` regenerates `src/rowcolumn_diacritics.rs`, kitty's Unicode placeholder diacritics, likewise; `scripts/bench.py` benchmarks; `TERMSHOT_PROFILE=1` prints stage timings as JSON on stderr; `scripts/release.sh <platform>` builds a release archive, with build.sh's flags plus `RUSTFLAGS='-C lto=fat'` (measured against the other size options in `docs/performance.md`, #83; not `panic=abort`, which would turn a caught panic into an abort).

## Architecture

The pipeline is Rust from the log to the PNG's bytes. The only C left is vendored stb (stb_truetype for the font tables and the rasterizer, stb_image_write for the PNG container) behind a thin glue file, `src/stb_glue.c`, and `src/image.c` around the PNG decoder; the Rust reaches stb_truetype only through the functions the glue hands it:

1. **`src/main.rs`** is the CLI, a thin one over the library's public API (#85): `parse_args`, the files, stdin and stdout, the output-alias checks, the cleanup on failure, and the wording of every message and exit status (`status` maps an `Error` to 1 or 2). It is a crate of its own, linking `libtermshot.rlib` with `--extern termshot` (build.sh builds the rlib first), and calls `termshot::parse_with_cell_size`, `Grid::set_cursor` and `termshot::render` and nothing but the public API; the CLI-only hooks (font load timings, the `-v` line, the profile record) are `termshot::cli` and `#[doc(hidden)]` items. Its own unit tests (argument checks, the warning's wording) are `src/cli_tests.rs`, built with `rustc --test src/main.rs --extern termshot=libtermshot.rlib` (`target/test/cli-unit`). The VT parser is **`src/vt.rs`**: the byte scans, escape and CSI dispatch, `utf8_at`, the routing of APC and DCS strings to kitty graphics and Sixel, and `replay_with`, which drives a `Screen` over the log (`parse`/`parse_lf`/`replay` are its test forms). The screen model is **`src/screen.rs`**: `Screen`, `Pen`, `Lf`, `CursorShape`, and the edit each control and SGR makes. It follows xterm: autowrap, scroll regions, the alternate screen, DEC graphics, and so on. The result is a **`src/grid.rs`** `Grid`: a flat `Vec<Cell>` of `cols*rows` (`Cell` is defined with its `attrs` bits in `src/cell.rs`), the marks, the cursor and the final image placements, with `to_text` and `to_json` (`--text`, `--json`).
   **`src/lib.rs`** is the library's crate root (#85): it declares every module and re-exports the public API, which lives in **`src/api.rs`** (`parse`, `parse_with_cell_size`, `Grid`'s accessors and cursor setters, `GridCell`, `ParseOptions`, `Palette`, casts, and `Error`) and **`src/api_render.rs`** (`Font`, `FaceSelector`, `FontSpec`, `RenderOptions`, `Cursor`, `render`, `render_rgba`, `Rendered`, `EmptyGlyph`). Errors are values: the library prints nothing, never exits, and returns `Error::OutOfMemory` where an allocation grows with its input (the crate docs list what still aborts); `render` catches a panic as `Error::Internal`. `render` prepares the cells as the CLI always has (**`src/prepare.rs`**: blank placeholders, the cursor, opaque backgrounds) so an embedder gets the CLI's bytes. The binary links the rlib like any embedder: two crates measured as fast as one compilation unit once the CLI was thin (`docs/performance.md`, "Two crates or one compilation unit"). The unit tests of every module, and the test modules (`src/tests.rs`, `src/draw_tests.rs`, ...), are `src/lib.rs`'s `#[cfg(test)]` modules, built with `rustc --test src/lib.rs` (`target/test/unit`). API items are `pub`, with `///` docs (`-W missing-docs` is clean); everything else in a module the API comes from is `pub(crate)`. `tests/library.rs` links `libtermshot.rlib` as an embedder does: the grids of `tests/grids/`, the PNGs of every pixel golden's case (`tests/golden_cases.rs`, shared with `tests/golden.rs`) byte for byte, every error, renders on twelve threads, hostile input, and with `--faults` (tests/run.sh) allocation failures. `src/cast.rs` decodes asciinema `.cast` input (v2 and v3) into the output bytes and the recording's size (the header's, or the last resize's) before any of this runs; it holds the strict JSON reader, which bounds nesting at `MAX_DEPTH`. `src/graphics.rs` handles the supported kitty direct-transmission subset; `src/image.c` wraps the vendored PNG decoder with a bounded allocator. `src/sixel.rs` decodes Sixel images (DCS `q`) as xterm does and feeds each to the kitty image store as a kitty command (`Graphics::sixel`, which wraps `Graphics::command`), so Sixel shares its layering, scrolling and limits; unlike kitty's, its pixels belong to the cells, and text and ED 0/1 clear them.
2. **`src/font.rs`** validates every TrueType structure stb_truetype will touch before C ever sees the font, because stb trusts its input. A font that fails is refused with a reason (exit 1). Fonts reach C with zero padding after them. JetBrains Mono is embedded with `include_bytes!` as the default.
   **`src/cff.rs`** reads CFF and CFF2 outlines (`.otf`, Noto CJK; CFF2 at any instance, whose coordinates `src/variations.rs` works out from fvar and avar as HarfBuzz does). stb's CFF reader trusts its input, so stb never runs a charstring: `font.rs` checks the CFF table with `cff::Font::parse`, and `src/glyphs.rs` gets each outline through the callback in the `#[repr(C)] Face` (`font::Font::with_face`), then has stb rasterize it with `stbtt_Rasterize`. On a CFF face, nothing may call stb functions that read glyph outlines (`IsGlyphEmpty`, `GetGlyphBox`, `GetGlyphShape`, `MakeGlyphBitmap`); cmap and metrics calls are safe. `src/stb_glue.c` hands glyphs.rs those four for a TrueType face only (`glyph_face`), and glyphs.rs refuses a face with both a callback and them (8). `src/cff_tests.rs` compares every glyph with stb's and builds hostile fonts; `docs/cff-rust-vs-c.md` is why this is Rust.
   **`src/metrics.rs`** varies the metrics at an instance, as HarfBuzz does: each advance by HVAR, through the Face's `advance` callback, and hhea's ascender, descender and line gap by MVAR, in its `ascent` and the rest. `src/stb_glue.c` reads a face's metrics only through `face_advance`, `face_v_metrics` and `face_scale`, and glyphs.rs passes each hmtx advance through the callback; neither uses stb's metrics of a face directly.
3. **`src/unicode.rs`** and **`src/unicode_tables.rs`** give character widths (wide = 2 cells) and canonical composition for combining marks.
4. **`src/render.rs`** drives a render, behind `render::draw`: it asks the glue for the fonts, allocates the raster (`alloc_zeroed`; a failure is an error, never an abort), runs the passes in order (the backdrop's init, the text (8), the images over the text (6), the cursor mark first among them), encodes the PNG and returns its bytes in a `Vec` (or the RGBA pixels), with the fields of the `TERMSHOT_PROFILE` record, whose keys and stage boundaries are draw.c's (`scripts/bench.py` and `docs/performance.md` compare across the move). It prints nothing and writes no file: each failure is a `Failure` with the CLI's message, which `src/api_render.rs` makes an `Error`. `draw_png_images`/`draw_png_with` (which print and write a file, as the CLI did) and `draw_png`, a cell-only `extern "C"` entry point, are for the unit tests and the C harnesses only (`cfg(any(test, termshot_render))`). It was C, draw.c's `draw_png_images`, until #12 step 2d; `bench/c-vs-rust/run.sh full` (CI runs it) compares PNGs, stderr and exit codes with that C through the CLI.
   **`src/stb_glue.c`** is the C that is left, and every function in it touches stb's own structs: `init_font`, `init_face`, `init_cff2` (stb's `stbtt_fontinfo`, which Rust can't see into), `cell_metrics` (also behind `draw_face_cell_size`, which `Font::cell_size` asks before replaying so native-pixel images move the cursor correctly, and `draw_cell_size`, its default-instance form for the C benches), `termshot_font_setup` (both faces, the metrics and the `TextFonts` table, with `glyph_face` setting stb's outline readers for a TrueType face only; it returns 1 or 2 for a face or metrics it can't use and prints nothing), and `termshot_png_encode` around `stbiw__write_png_from_filtered` of the locally modified `stb_image_write.h`, with `src/png_crc.h` for the CRC, `termshot_zlib_compress` (7) as `STBIW_ZLIB_COMPRESS`, and stb's PNG buffer from `termshot_png_alloc` (Rust, so the fault build can fail it). stb_truetype itself stays C (#12 step 3).
5. **`src/geometry.rs`** paints box drawing and block elements (U+2500–U+259F) as geometry, so lines join at any integer cell size, and keeps `Stamps`, the cache that repaints rounded corners and diagonals from the runs of an earlier stroke when a TwoSum check proves its points sit exactly as far from its cell's origin (4 MiB budget; a failed allocation stamps the stroke afresh, so geometry never fails a render). `src/glyphs.rs` calls it once per cell (`paint_cell`) and for underlines and missing-glyph boxes (`fill_rect`); `termshot_paint_geometry` and `termshot_fill_rect` remain for the C harnesses, and per-pixel calls across FFI are not allowed. The `Canvas` is `#[repr(C)]` and shared (40 bytes, asserted on both sides); its `geometry` pointer is the render's Rust state (`termshot_geometry_new`/`_free`/`_stats`). The float arithmetic is the C's, operation for operation in f32, and `sin_cos` calls the platform's sincos by name (`__sincosf_stret`, `sincosf`) because the C's compilers merged `sinf`/`cosf` into it and on macOS the two forms differ in the last bit (`bench/c-vs-rust/sincos.c`). `bench/c-vs-rust/run.sh geometry` (CI runs it) compares it pixel for pixel with the C it came from. It was C until #12 step 2a.
6. **`src/composite.rs`** paints the image layers into the same `Canvas`: kitty and Sixel images and the underline and bar cursors (solid 1x1 `ImageView`s), sampled nearest-neighbour in integers with crops (`src_*`) and clips (`clip_*`: scrolled slices, Unicode placeholder runs), blended as `(s*a + d*(255-a) + 127) / 255`, in kitty's three layers by z (below the backgrounds under `INT32_MIN / 2`, where only cells without `ATTR_OPAQUE` show them; under the text below 0; over it). It also paints the backdrop under the text: the cell backgrounds, then the two lower layers, a row of cells ahead of the glyphs over them (`Backdrop`, all at once for a raster under 16 MiB or with more than 64 images under the text). `src/render.rs` fills in a `Backdrop` it keeps in its frame (`termshot_backdrop_init`), `src/glyphs.rs` paints it a row at a time as the text reaches each row (`due`, then `termshot_backdrop_through`, timed there), and `src/render.rs` calls `termshot_paint_images` for the layer over the text. It allocates nothing; a panic (a bug, such as a crop outside its image) is caught, and `termshot_paint_failed` fails the render. `ImageView` is defined here. `bench/c-vs-rust/run.sh images` (CI runs it) compares it with the C it came from on random scenes and through the CLI. It was C until #12 step 2b.
7. **`src/deflate.rs`** is the compressor that PNG writer calls, through FFI: `STBIW_ZLIB_COMPRESS` is `termshot_zlib_compress`, a `#[no_mangle] extern "C"` function in the main crate. It is stb's deflate made faster, with byte-identical output (`tests/deflate_diff.c` checks it against stock stb). Its output buffer comes from libc `malloc`/`realloc`, because stb `free()`s it; every allocation is checked, and a failure returns NULL, which `src/render.rs` reports as out of memory (exit 2). Adler-32 uses SSE2 intrinsics on x86-64 and a 16-lane loop that LLVM vectorizes elsewhere; that loop's shape decides whether it vectorizes, so check the linked binary after changing it (`docs/c-vs-rust.md`). The C harnesses link it, `geometry.rs`, `composite.rs` and `glyphs.rs` (with `cell.rs` and `cff.rs`) as a static library (`tests/rust_lib.sh`), declared for them in `tests/termshot.h`; built with `--cfg termshot_render` the library has `render.rs` too, for `tests/draw.c` and `tests/glyphs.c`, which include `src/stb_glue.c`. It was C until #12 step 1.
8. **`src/glyphs.rs`** paints the text, once per render (`termshot_paint_text`): each cell's glyph from the font or else the fallback, through a 1024-slot cache (`Glyph`, `Glyphs::find`; the key is the code point with wide, italic and mark, the slot `(cp ^ (italic ? 512 : 0)) % 1024`, and a conflict replaces the slot); the fallback's scale, centering and shrinking to fit (#27/#47); italic as a 12° slant of the outline (`slant_outline`; box drawing stays upright); bold as a second blend a pixel right; the outlined box of a character neither font has, and the `EmptyGlyphs` report of empty glyphs; combining marks (`paint_marks`: drawn from the end of the character when left of their origin, centered otherwise; default ignorables and Hangul fillers draw nothing); then underlines, double underlines and strike-through. It paints the backdrop (6) a row ahead of the text, and box drawing through (5). stb stays C: `src/stb_glue.c` hands it `TextFonts` (152 bytes), two `GlyphFace`s (56) with stb's cmap, metrics and rasterizer functions, and stb's four outline readers for a TrueType face only; a CFF face's outlines come from `Face.outline` (`Outline`, a scratch buffer shared by the empty check and the drawing, invalidated when slanted). The float arithmetic is the C's, operation for operation in f32, and needs no libm call: floor, ceil and round are exact. A failed allocation (the slots, the scratch, a bitmap) returns 1 and `src/render.rs` fails the render ("glyph allocation failed", exit 2); a panic returns 3 ("painting failed"). It reports its timings and counters in `TextStats` (80). `bench/c-vs-rust/run.sh glyphs` (CI runs it) renders every fixture and generated logs with each kind of font at several sizes through the CLI built from the old draw.c and through this one, and compares the PNGs and stderr byte for byte. It was C until #12 step 2c.

The structs that cross into the C of the binary are `Face` (64 bytes, made by `src/font.rs`, read by the glue and `src/glyphs.rs`), `GlyphFace` (56) and `TextFonts` (152), which the glue fills in for `src/glyphs.rs`, `CellMetrics` (28) and `FontSetup` (504: two `stbtt_fontinfo`s, opaque 160-byte blocks to Rust, then `TextFonts` and `CellMetrics`, filled in place in `render.rs`'s frame because `TextFonts` points into it), and stb's `stbtt_vertex` (14, as `cff::Vertex`); the glue and the Rust assert each size. `Cell` (12, with its `ATTR_*` bits), `Canvas` (40) and `GeometryStats` cross only into the C harnesses, through `tests/termshot.h`, which asserts the same sizes. Change both sides together. All eight `attrs` bits are taken. Combining marks with no precomposed form live outside `Cell`, in `Screen::marks` (keyed by storage index, kept in step by every edit) and then `Grid::marks`, a sorted `CellMarks` list (cell index plus `MAX_MARKS` = 4 code points, in `src/cell.rs`) that `src/render.rs` passes on to `src/glyphs.rs`; `marks_of` looks a cell up.

Unit tests live in `src/tests.rs` and `src/draw_tests.rs` (both `#[cfg(test)]` modules of lib.rs), and beside the modules they test (`src/geometry_tests.rs`, `src/glyphs_tests.rs`, which drives the glyph code with fake stb functions, `src/deflate_tests.rs`, ...). They check the parser against the screens in `tests/vt/expected.txt` and `tests/vt/real/`. Pixel goldens (`tests/golden.rs`) hash *decoded RGBA pixels*, not PNG bytes, so encoder changes that keep the pixels don't break them. The same runs write `--text` and `--json`, compared byte for byte with `tests/grids/<log>.txt` and `.json`; `--update-goldens` rewrites all of them, and `tests/grids/check.py` checks that the JSON agrees with the text. The text rows are also what the `tests/vt/` checks compare, so the tmux references cover `--text`.

## Constraints that aren't obvious

- **Determinism across platforms is a feature.** The same input must give the same pixels on macOS arm64, x86-64 Linux, and aarch64 Linux, with glibc or musl. The C that is left (`src/stb_glue.c`, and with it stb_truetype's rasterizer and metrics) is built with `-ffp-contract=off` so Apple clang doesn't fuse multiply-adds, which would change pixels (px 46 is in the goldens to catch exactly this); a C harness that includes the glue is built the same way. Never add `-ffast-math`. The Rust painting code must not use `mul_add`, and calls libm's rounded functions as the C's compilers did (see `geometry.rs`; `glyphs.rs` needs none).
- The C is linked as a static library (`-l static=termshot_c`), not as bare objects, so rustc orders it before libc and libm. That ordering is what makes static musl and glibc on aarch64 link. `libtermshot.rlib` carries the same static library inside it (rustc bundles a `-l static` library into an rlib), so an embedder's link puts the C before libc and libm too. The glue calls back into the crate (`termshot_zlib_compress` and `termshot_png_alloc`), which links because the crate's own objects come first, and the crate calls the glue (`termshot_font_setup`, `termshot_png_encode`, `draw_face_cell_size`). Of the Rust, only `render.rs` names a symbol of the glue's: stb's functions reach `glyphs.rs` as pointers, so the harnesses' static library links without the glue unless built with `--cfg termshot_render`. The binary gets the C from the rlib, so its link line names no `-l`. Keep `build.sh`, `test.sh`, `tests/run.sh` and `scripts/release.sh` consistent if you change the link line.
- Local changes to vendored stb are listed in `third_party/stb/CHANGES.md`; record any new ones there. `stb_truetype.h` is unmodified.
- CLI exit codes are part of the contract: 0 done, 1 unreadable or unwritable file, malformed `.cast`, or bad font (`Error::Cast`, `Error::Font`), 2 bad arguments (including an image over 2^27 pixels, `Error::ImageTooLarge`, a cast larger than 500x200 without `--size`, and an output that names an input or another output) or an allocation failure in the parse (its screens), the render (its copies of the cells, the raster, stb's PNG buffer, the bytes returned), the glyph painting or the compressor (`Error::OutOfMemory`), or a panic in a painter (`Error::Internal`); `main.rs`'s `status` maps each error to its code, and its `Display` is the message. An allocation failure in the geometry caches is not a failure, the stroke is painted uncached. A failed run removes the output files it created (the PNG, `--text` and `--json`). It is quiet on success, except for the hint about `--lf-newline` and the warning for a character drawn as a box because a font maps it to an empty glyph (`src/glyphs.rs` reports it in `EmptyGlyphs`; `main.rs` words it). `test.sh` checks all of this, and `tests/run.sh` fails each compressor allocation (exit 2), the render's six (exit 2), the parser's (exit 2), each geometry allocation (same PNG), each glyph allocation (exit 2) and, on Linux, the raster's under `ulimit -v` (exit 2) in the CLI, then the parser's and the render's through the library (`Error::OutOfMemory`).
- A bare LF moves down without a carriage return, as in a real terminal. `--lf-newline` exists for logs not captured through a PTY, such as `tmux capture-pane`.
- User-visible changes go in `CHANGELOG.md` under `[Unreleased]`, in Keep a Changelog format.
